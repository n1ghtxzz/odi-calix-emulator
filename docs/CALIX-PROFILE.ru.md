# Настройка профиля Calix/E7

[English](CALIX-PROFILE.en.md)

Для ODI DFP-34X-2C2 с ODI Calix Emulator v1.0.0. Основа проекта —
[odi-oss автора AndreZiviani](https://github.com/AndreZiviani/odi-oss), GPL-2.0.
Шаблон и генератор не содержат данных какой-либо абонентской линии.
Генератор работает на компьютере с Python 3, не подключается к устройству,
не применяет настройки и не прошивает SFP.

## Что есть в шаблоне

`calix-e7.example.json` — пример геометрии с четырьмя логическими Ethernet
UNI, двумя POTS и VEIP в слоте 3. При включённом E7-профиле прошивка также
создаёт служебный UNI 0107 и второй VEIP 0302. Это программные представления:
у стика один физический Ethernet-интерфейс, телефонных разъёмов и Wi-Fi нет.
Если исходная ONU или профиль OLT отличаются, измените параметры, прежде
чем применять их. Число портов может менять план, который строит OLT.

Генератор создаёт записи `OMCI_FIXED_ME` для классов 65311 и 65319 на
выбранных UNI. Именно эта пара включает штатные модели E7: 241, 244,
251, 407, голосовую телеметрию 65280–65283 и Ethernet-счётчики 65311.
Порты POTS и VEIP учитываются отдельно. 65311 читает доступные аппаратные
счётчики физического UNI; программные порты имеют нулевые счётчики.
Голосовая телеметрия стика не измеряет звонки внешней АТС.

Это не универсальная копия MIB любого Calix. Все неизвестные vendor ME и
аппаратные функции не воспроизводятся автоматически. Не добавляйте в
профиль старые мосты, GEM, T-CONT, очереди, Alloc-ID и сессии исходной ONU:
их заново назначает OLT. Аппаратный DSCP remap 52 пока не реализован.

## 1. Соберите собственные параметры

Сохраните полный дамп и конфигурацию своего стика. Запишите параметры
исходной ONU и требования оператора: GPON-серийник, способ авторизации,
версии, геометрию портов, используемые VLAN и приоритеты. Берите значения
из своего оборудования или у оператора, а не из чужого примера.

| Поле JSON | Значение и действие |
|---|---|
| `identity.GPON_SN` | Собственный GPON SN: 4 символа vendor ID и 8 hex-цифр, всего 12 символов. Это не произвольный номер из биллинга. `null` сохраняет текущий SN. |
| `identity.GPON_ONU_MODEL` | Equipment ID, до 20 ASCII-символов; задавайте только если он нужен вашему профилю. |
| `identity.ONU_HW_VERSION` | Версия оборудования, до 14 ASCII-символов. |
| `identity.OMCI_SW_VER1/2` | Версии двух образов, каждая до 14 ASCII-символов. |
| `identity.OMCC_VER` | Десятичное число 0–255. |
| `identity.OMCI_VENDOR_PRODUCT_CODE` | Десятичное число 0–65535. |
| `ethernet_ports` | От 1 до 4, включая физический UNI 0101. |
| `compatibility.OMCI_POTS_PORTS` | 0, 1 или 2; для отсутствующей телефонии задайте 0. |
| `compatibility.OMCI_POTS_SLOT_ID` | Слот POTS, обычно 2; не 1, 6, 128 и не включённый слот VEIP. |
| `compatibility.OMCI_VEIP` | 0 или 1. При 0 служебные дополнения VEIP отключены. |
| `compatibility.OMCI_VEIP_SLOT_ID` | Слот VEIP; 3 соответствует 0301 и 0302. |
| `compatibility.OMCI_CUSTOM_ME` | Битовая маска. Для собственного слота VEIP нужен бит 0x100. Пример 256 содержит только этот бит. Если нужны прежние флаги, сохраните их: `прежняя_маска | 256`, затем запишите результат десятичным числом. |
| `management_ip` | Свой адрес управления IPv4 без маски либо `null`, чтобы не менять его. |

`OMCI_PRIVATE_ME=0` убирает обычные приватные модели 350/370/373, а не
добавленные модели Calix. `OMCI_UNKNOWN_ME_OK=1` сохраняет режим совместимости
для неподдерживаемых запросов; успешное подтверждение такого запроса не
означает реализации соответствующей функции. Оба параметра в примере включены
осознанно и могут требовать изменения для другого OLT.

Поля `identity` по умолчанию равны `null`: генератор не записывает их в seed.
Пустая строка не заменяет `null` и отклоняется. Если все поля пусты, файл
`identity.env` вообще не создаётся и переключатель идентификации не включается.
Для `GPON_ONU_MODEL` и `OMCI_SW_VER1/2` seed поддерживает токены из латинских
букв, цифр, `_`, `.` и `-`, без пробелов; это ограничение добавления отсутствующего
поля в конфигурацию. Не копируйте завершающие пробелы из бинарного MIB.

PLOAM, LOID, пароль LOID и SIP-пароль намеренно не входят в шаблон. Штатный
first-boot seed их не принимает. Настройте нужный способ авторизации через
Config → ONU identity своего стика; сохранённые значения шаблон не стирает.
PLOAM допускает текст длиной 1–10 символов, ровно 20 hex-цифр либо `0x` с
2–20 чётным количеством hex-цифр. Не публикуйте заполненный профиль.

## 2. Подготовьте каталог профиля

Распакуйте `calix-e7-template-v1.0.0.zip`. Внутри есть JSON, генератор,
две инструкции и лицензия. На Linux/macOS:

```sh
umask 077
PROFILE_WORKDIR=$(mktemp -d)
cp calix-e7.example.json "$PROFILE_WORKDIR/line.json"
# Отредактируйте line.json своим текстовым редактором.
python3 prepare-calix-profile.py "$PROFILE_WORKDIR/line.json" \
  --output "$PROFILE_WORKDIR/generated"
```

В исходниках генератор находится в `tools/prepare-calix-profile.py`, JSON —
в `examples/calix-e7/`. На Windows используйте `py -3` вместо `python3` и
выберите отдельный личный каталог вне Git. Генератор не перезаписывает
существующий результат и отказывается создавать личный профиль внутри Git.

Результат: `generated/seed/id`, `odi.conf`, а при заданных полях также
`identity.env` и `lan-ip`. `id` — SHA-256 содержимого, а не серийник ONU.
Он нужен для однократного применения seed: одинаковый профиль повторно
не затирает изменения владельца. На Unix каталог имеет права 0700,
файлы — 0600. Генератор не выводит значения идентификации в консоль.

## 3. Выберите способ применения

**Готовый публичный образ, без дополнительного OME1.** Сначала настройте
доступ по SSH-ключу через вебку. Убедитесь, что `generated/emulation.bin`
отсутствует. Задайте `ONT_IP` адресом своего стика и скопируйте seed:

Каталог `/tmp/calix-seed` должен отсутствовать. Если он остался от предыдущей
попытки, выберите новое имя каталога и замените его в обеих командах,
чтобы не сохранить старый `identity.env` вместе с новым профилем.

```sh
scp -O -r "$PROFILE_WORKDIR/generated/seed" "root@$ONT_IP:/tmp/calix-seed"
ssh "root@$ONT_IP" 'ODI_PROFILE_DIR=/tmp/calix-seed /etc/scripts/profile-seed.sh'
```

Это уже записывает настройки в конфигурацию, но не выполняет Apply,
перезагрузку или Commit. Проверьте значения в вебке и примените изменения
OMCI только в подходящее время: повторная регистрация прервёт связь.
Профиль сохраняется в конфигурационном разделе; файлы в `/tmp` — временные.
Этот способ не устанавливает бинарный overlay в корневую ФС.

**Собственная сборка с seed.** В исходниках v1.0.0 соберите образ на Linux
с Docker, используя абсолютный путь к личному каталогу:

```sh
PROFILE_DIR="$PROFILE_WORKDIR/generated/seed" \
  ROOT_PW=locked VERSION=odi-calix-myline make image-all
```

Если генератор создал `emulation.bin`, добавьте его отдельно:

```sh
PROFILE_DIR="$PROFILE_WORKDIR/generated/seed" \
  EMULATION_PROFILE="$PROFILE_WORKDIR/generated/emulation.bin" \
  ROOT_PW=locked VERSION=odi-calix-myline make image-all
```

Новый образ содержит ваши личные поля; храните его приватно. Запишите его
в неактивный раздел, используйте Try и закрепляйте вручную только после
проверки. Генератор не создаёт и не меняет пароль SSH; `ROOT_PW=locked`
оставляет доступ по ключам. Первичная веб-авторизация без прежних настроек —
admin/admin, после чего задайте свой пароль.

## Необязательные поля отчётности

`reported_mfg_serial` — собственный заводской номер для ME 241, ровно
12 ASCII-байт. Это ширина текущей модели совместимости, а не обещание
универсальной схемы для любого Calix. `reported_ip_host_macs` — словарь
`"десятичный instance ME 134": "xx:xx:xx:xx:xx:xx"` для своих IP host.
Номера экземпляров смотрите в MIB своей линии. По умолчанию номер равен
`null`, словарь пуст — никакие значения не подставляются.

Если поля заполнены, генератор создаёт проверяемый OME1 `emulation.bin`:
только ME 241/0 attribute 1 и ME 134/нужный instance attribute 2.
Они меняют ответы OMCI, но не MAC интерфейса, DHCP-клиент, адреса IP и VLAN.
Файл нужно включить в собственную сборку, как выше. На v1.0.0 путь
`/etc/omci-emulation.bin` фиксирован и находится в read-only корневой ФС;
копирование в `/etc/config` не устанавливает overlay. Не включайте
`OMCI_EMULATION=2`: этих полей хватает в штатном строгом режиме. Если
раньше overlay был выключен, задайте `OMCI_EMULATION=1` через настройки
или `/etc/scripts/flash set OMCI_EMULATION 1` перед следующей регистрацией.

## Проверка линии

После пробной загрузки проверьте управление, O5, VLAN и выданные OLT
T-CONT/GEM, DHCP интернета, обе стороны трафика и телефонию. O5 подтверждает
регистрацию PON, но не получение услуги. VLAN и приоритеты берите из своей
линии: универсальных номеров в шаблоне нет. Стик не регистрирует SIP сам:
для звонков нужен SIP-клиент/АТС за ним и собственные параметры телефонии.

Читайте `/var/log/omcid.log`, MIB Browser и OMCI → Services/Phone. Журналы,
дампы и заполненный JSON могут раскрывать идентификацию и SIP-данные;
не прикладывайте их к публичному issue без удаления этих полей.
При неуспешной пробе вернитесь в закреплённый раздел и восстановите
сохранённую конфигурацию: раздел настроек общий, смена слота его не откатывает.
Ни генератор, ни этот комплект не коммитят пробную прошивку автоматически.
